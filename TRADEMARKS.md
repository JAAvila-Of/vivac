The name **vivac** and its logo identify this project and the releases its
maintainer publishes. This page says how they may be used. It does not change
the licence of the code.

## What is covered

Jóse Angel Avila owns the name **vivac** where it names software — a
command-line tool, a package, a project — and the logo that goes with it.

The ordinary word is not claimed: a vivac is Spanish for a bivouac, and
anybody may keep using it for that. Nor does this page claim that the mark is
registered anywhere.

## The licence covers the code, not the name

The code is `MIT OR Apache-2.0`. Either licence lets you copy, change and
redistribute it, and neither lets you use the name or the logo: Apache-2.0
says so in its section 6, and MIT says nothing about names at all.

## What you can do without asking

- Say what is true: that something works with vivac, reads a vivac tree, is
  built on it or was forked from it, and link here.
- Write about it, review it, teach it, compare it with anything else.
- Use the name in plain text to refer to this project.

## Forks and modified builds

A fork needs nobody's permission; the licence already gives it. It does need a
name and a look of its own. A modified build published as `vivac`, or under a
name or a logo close enough to be taken for it, puts this project's name on
code this project never shipped, and the people who trust that name are the
ones who pay for it.

A fork may say it is based on vivac, as long as that does not read as
official.

- use the name or the logo in a way that suggests this project endorses,
